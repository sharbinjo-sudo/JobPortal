# Architecture

The Django `portal` app owns the normalized user, profile, company, job, application, and history models. API authorization is enforced server-side with JWT and role permissions. Flutter is a single Material 3 client with role-aware presentation and a repository-facing API service. PostgreSQL (Supabase) is the only supported database — `DATABASE_URL` is required and SSL is always forced; tests run against a throwaway SQLite file. Media (resumes, company logos) is stored in a private Supabase Storage bucket via the S3-compatible gateway (`config.storage.SupabaseMediaStorage`, django-storages + boto3) when `SUPABASE_S3_*` is configured, with local-disk fallback for dev/tests; every download URL is re-signed per response as a short-lived presigned link, and service-role credentials remain backend-only.
